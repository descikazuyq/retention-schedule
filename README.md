# 本地保管期限与销毁清册

这是一个在本机运行的本地保管期限与销毁清册。只登记条目元数据，不读取或保存真实文件。

## 使用

```bash
go test ./...
```

调用者先选择一个本地保存位置并打开，然后即可办理各项业务：

```go
s, _ := retention.Open("/path/to/vault")
defer s.Close()

s.Register(retention.RegisterInput{
    ID: "A-001", Category: "合同",
    Start: retention.MustParseDate("2020-01-01"),
    End:   retention.MustParseDate("2025-01-10"),
})

s.Freeze(retention.FreezeInput{
    ArchiveID: "A-001", FreezeID: "F-1",
    Reason: "诉讼", FrozenOn: retention.MustParseDate("2025-01-08"),
})
s.Release(retention.ReleaseInput{
    ArchiveID: "A-1", FreezeID: "F-1",
    Reason: "结案", ReleasedOn: retention.MustParseDate("2025-01-09"),
})

// 销毁前可先只做核对：不销毁、不生成清册、不占用申请编号。
r, _ := s.Check(retention.CheckRequest{
    ApplicationID: "APP-2",
    ProcessedOn:   retention.MustParseDate("2025-01-10"),
    ArchiveIDs:    []string{"A-001"},
})
switch r.Status {
case retention.CheckReady:       // 可以办理
case retention.CheckBlocked:     // 存在阻碍，见 r.Results
case retention.CheckReplayable:  // 可以取回原清册，见 r.Manifest
case retention.CheckConflict:    // 申请编号冲突，r.Manifest 附原清册
}

m, err := s.Destroy(retention.DestructionRequest{
    ApplicationID: "APP-1",
    ProcessedOn:   retention.MustParseDate("2025-01-10"), // 截止日当天即到期
    ArchiveIDs:    []string{"A-001"},
})
_ = m

h, found, _ := s.History("A-001") // 登记内容、全部冻结解除历史、销毁状态与清册
_, found, _ = s.GetManifest("APP-1")
```

## 规则要点

- 日期统一 `YYYY-MM-DD`，按日历日期比较，不受时区或夏令时影响；日期必须真实存在。
- 登记：编号、类别不可空白；截止日不能早于起算日；重复编号明确失败且不影响已有记录。
- 冻结：同一档案可有多条，冻结编号同档案内唯一；解除必须填日期和原因，解除日期不早于冻结日期；
  解除只做标记，记录全部保留；不能给不存在或已销毁的档案新增冻结。
  读取保存内容时同样沿用编号唯一规则：一份档案的全部冻结历史中，一个冻结编号只能出现一次，
  解除过的记录仍占用原编号。只要同一档案保存了两条相同编号的冻结，就把整份保管库视为记录损坏——
  两条都未解除、一条已解除而另一条未解除、或两条均已解除结果相同，即使原因、冻结日期与解除信息
  完全一致也不能合并成一条或只挑一条使用；错误按 ErrCorruptState 判断，明确给出档案编号与重复的
  冻结编号，说明同一档案的冻结历史出现重复。唯一性只限同一份档案：不同档案各有一条同编号冻结仍是
  合法情况，解除其中一份档案的冻结不影响另一份。已销毁档案的冻结历史同样遵守这条规则，即使其全部
  冻结已经合法解除、所属清册、期限和处理日期都正确，重复编号仍被拒绝。打开保管库时发现这种情况即
  明确失败，不返回可继续办理的保管库；库已经打开后保存内容才出现重复编号的，下一次使用有效输入
  查询历史、取回清册、销毁前核对或办理业务（含解除申请——不得挑一条同号记录写入原因和日期，以及
  销毁申请——不得生成清册；即使本次查看或操作的是另一份正常档案）同样按整库记录损坏失败，不返回
  正常历史、清册或部分核对报告，不产生业务变更；原保存文件保持原样，不改冻结编号，不删除、合并或
  自动解除重复记录来消除问题。
  读取保存记录时还会核对冻结状态与销毁记录：仍被冻结的档案不能销毁，销毁后的历史也遵守这条
  规则。档案已标记为已销毁、所属清册存在，清册归属、条目内容和处理日期都合法，但该档案仍有
  一条冻结标记为未解除时，即使其他冻结已经解除、即使这条记录残留了解除日期或解除原因，也按
  保存记录损坏拒绝打开（ErrCorruptState），错误指出档案编号、未解除的冻结编号和所属清册申请
  编号；解除与否只沿用保存的解除标记判断，残留的解除日期、原因不能当作已解除。一份清册收录
  多份档案时任一份存在这种矛盾即整库不可读，不返回其余正常档案的记录，也不自动解除冻结、
  删除冻结历史、修改销毁标记或重建清册来消除冲突。保管库打开后保存内容才出现这类矛盾的，
  下一次使用有效输入查询历史、取回清册、销毁前核对或办理业务（含操作不在该清册中的档案）
  同样报整库记录损坏，不返回正常历史、清册或部分核对报告，不产生业务变更，原保存内容保持
  原样。尚未销毁的档案保留未解除冻结仍是合法状态，可正常查看并在销毁前核对中显示冻结阻碍；
  已销毁档案没有冻结，或全部冻结均已合法解除时，历史和清册继续完整可查。
- 修订：尚未销毁的档案（含被冻结的）可延长或缩短保管截止日，不必重新登记，编号、类别、起算日不变；
  新截止日不早于起算日且不等于原截止日。首次办理时所提交的原截止日必须与当前保存值一致，
  否则返回期限已变化错误并附当前截止日。修订编号全库唯一、与销毁申请编号互不占用；
  同编号同内容重试取回首次记录，改任何一项即编号冲突；失败不留历史，失败编号可再提交。
  打开保存位置时还会核对已保存历史：每个成功修订编号只能对应一条保存的修订记录，
  同一档案历史中重复编号、不同档案保存同号修订（即使内容相同）或编号与已关闭清册
  申请编号相同，都按保存记录损坏拒绝打开（ErrCorruptState），不合并、不挑选记录；
  保管库打开后保存内容才出现此类冲突的，下一次查询、核对或办理同样报记录损坏，
  冲突属于整库且原保存内容保持原样，不自动改编号、删除历史或重建清册。
  已关闭清册中的每条档案条目是销毁成功那一刻的登记内容快照，其类别、起算日和
  截止日必须与对应档案保存的登记内容逐项一致：截止日取销毁时最终生效的期限
  （最后一次成功修订的新截止日，没有修订时为最初登记的截止日），即使修订历史
  衔接完整、清册归属正确，清册保存成最初登记的截止日（延长、缩短或改回早先用过
  的日期均同此规则，不按修订办理日期重新挑选）也按保存记录损坏拒绝，错误指明
  清册申请编号、档案编号与不一致的项目；一份清册收录多份档案时任一条目矛盾即
  整库不可读，不挑选可信记录，也不能靠覆盖清册、修改档案或删除记录消除差异。
  保管库打开后保存内容才出现这类差异的，下一次使用有效输入查询、销毁前核对或
  办理业务同样报整库记录损坏，不返回正常历史、清册或部分报告，不产生业务变更，
  即使本次操作的档案不在那份清册中也一样，原保存内容保持原样。
  已关闭清册还必须带有处理日期，且处理日期不能早于任一条目档案销毁时最终生效
  并保存到清册里的截止日——沿用办理销毁时同一条到期规则（截止日当天即到期）：
  缺少处理日期（缺失或为 null）不能当作已经办理的销毁日期，按保存记录损坏拒绝
  打开，错误指出申请编号；处理日期早于所收录任一档案的截止日属于提前销毁，即使
  该档案标记为已销毁、清册归属与条目快照都一致，也按保存记录损坏拒绝，错误同时
  指出申请编号、档案编号、处理日期和截止日。期限修订过的档案按清册条目保存的
  最终截止日判断（延长、缩短或改回早先用过的日期都一样），不按修订办理日期重新
  挑选另一版期限。一份清册收录多份档案时任一份未到期即整库不可读，不返回其余
  已到期档案的正常记录，也不略过未到期条目，不通过补处理日期、改期限、改销毁
  标记或清册条目消除矛盾。保管库打开后保存内容才出现此类问题的，下一次使用有效
  输入查询历史、取回清册、销毁前核对或办理业务（含操作不在该清册中的档案）同样
  报整库记录损坏，不返回正常结果或部分核对报告，不产生业务变更，原保存内容保持
  原样。合法清册在截止日当天或之后处理，历史与清册保持完整可查。
  历史核对同时给出最初截止日、当前截止日和按成功顺序排列的全部修订记录。
- 核对：销毁前的只读核对，一次看清整批所有阻碍。申请编号尚未成功使用时，按提交顺序逐份给出
  类别、起算日、截止日、销毁状态和全部适用阻碍（不存在、已销毁、未到期、仍有未解除冻结，可逐一识别）；
  未到期与多条未解除冻结并列显示，每条冻结带编号、原因和冻结日期；已销毁档案附所属清册申请编号与处理日期；
  全部无阻碍才显示可以办理。申请编号已成功使用时，日期与档案集合相同（顺序无关）显示可以取回原清册，
  改变日期或集合则显示申请编号冲突，二者均附原清册。空白编号/日期、空名单、重复编号或读取记录失败时
  整次核对明确失败，不返回部分报告。
- 销毁：一次可多选；只有全部存在、到期、未销毁、无未解除冻结时才整体成功并生成已关闭清册，
  清册条目按关闭瞬间的登记内容保存类别、起算日和当时最终生效的保管截止日。
  空名单、名单重复或任一不符条件时整次失败，不留部分销毁或清册。
- 幂等：已成功的申请以相同日期和档案集合（顺序无关）重放返回原清册；沿用编号改日期或集合则失败；
  失败的申请条件改变后可用同编号重试。
- 并发：多个本机程序同时办理时以文件锁决定先后，先成功的冻结挡住销毁，先成功的销毁挡住后续冻结。
  核对在共享锁内读取同一已保存状态，一份报告不会混入操作前后的不同结果；核对之后状态若变化，
  正式提交仍按最新状态判断。
